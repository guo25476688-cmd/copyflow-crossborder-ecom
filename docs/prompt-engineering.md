# Prompt 工程设计

> Prompt 原文见 [`../workflow/prompts/`](../workflow/prompts/)。本文讲设计原则、逐平台设计决策、踩坑与迭代记录、关键权衡。

## 1. 设计原则

### 1.1 为什么每个平台要独立 System Prompt，而不是通用 Prompt + 参数

四个平台的内容逻辑存在**根本差异**，不是「同一篇文案改改格式」能覆盖的：

- Amazon Listing 以 SEO 为核心，要求关键词精准嵌入、规避违禁词
- Shopee 强调性价比感知和促销氛围，高频 Emoji + 本土促销话术
- TikTok 的核心是情绪钩子和口播节奏，功能介绍型文案几乎没有完播率
- SHEIN 卖的是生活方式认同，功能参数会被划走

用一个通用 Prompt 靠变量切换，等于让模型在生成时同时兼顾四套互相冲突的约束，结果是四个平台都不到位。独立 Prompt 让每个分支的约束**方向单一、可检查**。

### 1.2 如何平衡「平台合规」与「内容创意」

以约束的**方向**来区分平台，而不是靠调 temperature：

| 平台 | 约束方向 | Prompt 表现形式 |
|---|---|---|
| Amazon | 合规驱动——约束「不能有什么」 | 末尾「规则检查清单」+ 违禁词黑名单 |
| Shopee | 转化驱动——约束「必须有什么」 | 强制 Emoji、促销标签、长尾词、字符下限 |
| TikTok | 结构驱动——约束「按什么顺序」 | 显式时间轴（0–5s / 5–15s / 15–35s / 35–50s） |
| SHEIN | 调性驱动——约束「先定调再展开」 | 「风格笔记」前置模块 + 感官词汇要求 |

所有平台 temperature 统一 0.7：结构化约束已经由 Prompt 结构承担，不需要再靠低温压制发散。

### 1.3 Context 注入策略

三源数据在**节点 4（卖点结构化）**汇聚，而不是各自灌进平台 Prompt：

```
RAG 本地热词  ┐
Tavily 实时SEO ┼─→ 节点4 强制降维为四维结构 ─→ 平台 Prompt 只消费结构化结果
原始产品特性  ┘
```

好处：平台 Prompt 的输入永远是干净的四维结构，不受检索噪声影响；三源融合的复杂度集中在一个节点，便于调试。

## 2. 逐平台设计决策

### Amazon Listing

**目标张力**：SEO 权重（标题需嵌入核心词+品牌+属性+场景，密度影响排名）与合规（`best` / `#1` / `guarantee` 等词会导致降权甚至下架）必须在同一个 Prompt 里同时约束。

**输出结构固定为三层**：标题（80–200 字符）、五点描述（每点加粗小标题 + 描述）、产品描述（段落，侧重情感与场景）。

**关键决策——Prompt 末尾加「规则检查清单」**
早期即使 System Prompt 写明「禁止 sale/discount」，模型在生成靠后的五点描述时仍会偶发违规，因为生成是逐 token 的，靠前的约束对靠后的内容控制力衰减。在 Prompt 末尾加显式检查清单（相当于生成结束前的一次自我校验提示）后，违规率从约 15% 降到接近 0。

### Shopee Listing

**目标**：匹配 Shopee 的两个特征——搜索侧依赖长尾词（如 `wireless earbuds waterproof sport` 而非 `earbuds`），展示侧依赖视觉热闹感。Shopee 买家决策链路短、冲动购买比例高。

**关键决策——硬编码本土促销词**
只告诉模型「口语化、热情」，生成的内容风格接近但缺少能触发东南亚买家行动的信号词。`gratis ongkir`（包邮）、`Ready Stock`（现货）对印尼买家是购买决策的高频触发词，不出现就是流失转化。把这些词显式写进 Prompt，比让模型自己判断「什么词更本土」稳定得多。

### TikTok 短视频脚本

**本质差异**：TikTok 文案不是商品描述，是一段完整口播脚本。核心目标是完播率和互动率，不是搜索排名。前 5 秒决定算法分发量级。

**关键决策——显式时间轴结构**
不加时间轴时，模型生成的脚本语言流畅但结构是「介绍产品 → 说功能 → 说价格」的线性叙事，不符合 TikTok 节奏。加入 `0–5s 钩子 / 5–15s 痛点 / 15–35s 方案 / 35–50s CTA` 后，结构命中率显著提升。时间轴的作用是**逼模型以「观众注意力分配」而非「产品功能逻辑」组织内容**。

另一处约束：Amazon/Shopee 的输出是「被阅读的文字」，TikTok 的输出是「被朗读的台词」——句子要短、有停顿感、适合真人发音，用「口语化、适合真人发音、80–150 字」显式指定。

### SHEIN 风格文案

**目标**：生成有「生活方式感」而非「功能介绍感」的文案。写「防皱面料、透气性好」会被划走；写「随手一穿就有度假感，周末早晨、咖啡馆、机场候机都能 hold 住」才会停下来看。

**关键决策——「风格笔记（Style Notes）」前置模块 + 感官词汇**
「风格笔记」要求模型先用 1–2 句话确立时尚氛围，再展开描写，对调性校准效果最明显。感官词汇（`丝滑的垂感`、`轻盈到几乎感觉不到重量`）不显式要求的话，模型默认生成功能性描述，感官词密度很低。

### 本地化翻译

**为什么不用翻译 API 而用 LLM**
翻译 API 解决语言转换，跨境电商本地化要解决**文化适配**。`Free Shipping Available` 直译成印尼语 `Pengiriman Gratis Tersedia` 语义正确但生硬，而真正触发购买的是 `gratis ongkir`——印尼买家每天在 Shopee/Tokopedia 看到的高频促销词。翻译 API 不做这种替换，LLM 配合显式本土化指令可以。

定位是「本地化编辑」而非「翻译工具」：保留核心卖点和排版结构，把语言风格、促销话术、表达习惯整体替换成目标市场的本土标准。

**保留 Markdown / Emoji 的三条硬约束**
LLM 翻译时注意力集中在语言转换，常见三类问题：`###` 标题层级丢失、加粗符号被吞、Emoji 被替换成文字或删除。解决方式是在输出要求里写死：① 严格保留 Markdown 层级和排版符号；② Emoji 原位保留不替换不删除；③ 直接输出结果，不要「好的，以下是翻译」这类前缀（批量处理时会污染下游解析）。还发现部分模型会把 `Ready Stock ｜ Fast Shipping` 的全角竖线改成逗号，破坏视觉节奏，追加「严格保留 ｜、【】等分隔符」后消除。

## 3. 迭代记录

| # | 问题现象 | 根本原因 | 解决方案 | 效果 |
|---|---|---|---|---|
| 1 | 五点描述被输出成 JSON 数组 `["卖点1","卖点2"]`，无法直接复制 | 训练数据里大量结构化任务是 JSON 格式，模型默认「结构化 = JSON」 | Prompt 中明确「请生成纯文本排版的文案，切勿使用 JSON 格式」，并用 Markdown 示例直接展示期望格式 | 模型优先模仿示例格式，问题基本消除 |
| 2 | Amazon 五点描述偶发出现 `sale` / `discount` 等违禁词（约 15%） | 生成是逐 token 的，靠前的「禁止违规词」约束对靠后内容控制力衰减 | Prompt 末尾追加显式「规则检查清单」，等于生成结束前做一次自我校验提示 | 违规率从 ~15% 降到接近 0 |
| 3 | TikTok 脚本语言流畅但结构是「介绍→功能→价格」的线性叙事，不符合平台节奏 | Prompt 只给了角色和风格，没给结构 | 加入显式时间轴（0–5s 钩子 / 5–15s 痛点 / 15–35s 方案 / 35–50s CTA） | 结构命中率显著提升，强制模型按注意力分配组织内容 |
| 4 | 多语翻译后 Emoji 丢失、`｜` 被改成逗号、出现「好的，这是您的翻译」前缀 | LLM 翻译时注意力集中在语言转换，忽略排版符号；礼貌性前缀是对话习惯 | 输出要求里写死三条硬约束（保留 Markdown、Emoji 原位、纯文本直出无前缀），并追加「保留 ｜【】分隔符」 | 排版稳定，下游文本解析不再被污染 |

## 4. 关键权衡

- **迭代节点 vs 单次多语输出**：让单个 LLM 一次生成多种语言，随语言数增加会出现语言混杂、Markdown 坍塌、token 溢出。迭代方案为每种语言开独立推理沙箱——物理隔离防污染、无限扩展避免截断、直接输出结构化数组。代价是调用次数 = 语言数，延迟线性增长。
- **免费模型 vs 付费模型**：原型阶段用 OpenRouter 免费模型（`trinity-large-preview:free`、`minimax-m2.5:free`），目的是零成本验证 Prompt 与架构，而非验证模型性能。代价是速率受限、输出稳定性偏低、偶发格式错乱。产品化阶段再做模型选型。
